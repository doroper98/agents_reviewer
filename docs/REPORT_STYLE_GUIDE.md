## 0. 기본 원칙 — 친절한 편집자의 목소리

본 시스템의 보고서는 사건의 사실과 의미를 *일반 독자에게 차분히 설명* 하는 글이다.
신문 칼럼·잡지 에세이의 극적 톤을 흉내내지 않고, 분석가가 동료에게 던지는 메모 톤도
아니다. 그 중간 — **친절한 편집자가 차근차근 풀어주는** 톤이다.

세 기둥:
1. **평이함** — 학부생 수준 어휘. 한자어·외래어·전문 용어는 처음 등장 시 한 줄 풀이.
   한 문장에 새 개념 0~1개.
2. **친절함** — 독자가 막히지 않게. 모르는 개념은 풀이, 모르는 지명은 위치, 모르는
   사건은 한 줄 배경.
3. **절제** — 과장·단정·감탄·극적 강조 자제. 추정은 보수 표현, 사실은 출처와 함께.

### 0.1 ★ 최우선 가치 — 일반 독자 우선 (모든 규칙에 앞선다)

독자는 *해당 분야 비전문가* 다. 아래 두 가지가 본 시스템의 **가장 중요한 가치**이며,
이 문서의 다른 어떤 문체·구성 규칙보다 우선한다. composer / context SYSTEM_PROMPT,
템플릿, 회귀 테스트 모두 이 원칙을 향한다.

1. **평이한 우리말로 바꾼다.** 전문 용어·영어 표현·업계 은어를 그대로 쓰지 않고
   일반 독자가 아는 말로 옮긴다. 뜻이 정확히 보존되면 *반드시* 바꾼다 (§2.1 어휘표).
2. **불가피한 전문 용어는 그 문단 하단에 주석으로 푼다.** 평이한 말로 바꾸면 의미가
   훼손되는 핵심 용어만 본문에 남기고, 그 용어가 등장한 섹션의 본문 *하단* 에
   "용어 풀이" 각주로 한두 문장 설명한다 (§2.2 — `ComposedSection.footnotes`).

평이한 말로 바꿀 수 있는데 주석으로 떠넘기지 말 것. *먼저* (1) 을 시도하고, 정말 못
바꿀 때만 (2). 이 원칙 위반은 WRITE-AP-10 회귀로 기록된다.

> **(1-예외) 고유명사는 평이화·음차 대상이 아니다 — 원어 표기 보존 (v7.9.6, WRITE-AP-24).**
> 회사·제품·서비스·모델·브랜드·기관 이름 같은 고유명사는 한글로 음차(소리만 옮겨
> 적기)하지 않고 *원래 표기 그대로* 쓴다. 통용 표기가 로마자(영문)인 이름은 영문으로:
> `DeepSeek`(딥시크 X) · `Copilot Cowork`(코파일럿 코워크 X) · `OpenAI`(오픈AI X) ·
> `Anthropic`(앤트로픽 X) · `Azure`(애저 X) · `Fable 5`(페이블 5 X) · `GitHub Copilot` ·
> `Meta` · `Mistral`. 단 한국 언론에서 한글로 굳어진 이름(마이크로소프트·나스닥·로이터·
> 트럼프)은 그대로 한글로 둔다. 외래어 *일반 용어*(opt-in 등)도 음차(옵트인) 대신
> 원표기(opt-in)로 쓰고, 뜻이 어려우면 (2) 의 각주로 푼다.
>
> ★ **보고서와 영상 음성 내레이션의 분리.** 한글 음차(딥시크·오픈AI·애저)는 *영상
> 음성 대본(`narration_tts`) 전용* 이다. 본문 prose·headline·deck·heading·각주·
> `broadcast_summary`·자막(`narration`) 같이 *눈으로 읽는 글* 에는 원어 표기를 쓴다.
> 음차가 눈으로 읽는 글로 새면 WRITE-AP-24 회귀. (TTS 발음 표기 누수 WRITE-AP-23 의
> 자매 회귀 — 둘 다 음성 전용 표기가 글로 번진 것.)

## 1. 어조 (Voice)

### 1.1 평어체 (필수)
- `~다 / ~한다 / ~이다`. 음슴체 (`~함`, `~임`) 금지.
  - 좋음: "베르베라는 35년 만에 다시 미국과 협력했다."
  - 나쁨: "베르베라는 35년 만에 다시 미국과 협력함."

### 1.2 차분한 설명 톤
- 편집자가 독자에게 *차근차근* 설명하는 톤. 분석가의 메모 톤 X.
- 단정·감탄 자제. *거대한 / 결정적인 / 충격적인 / 운명의 / 격동의* 같은 극적 형용사
  사용 빈도 ≤ 0.5/섹션 (즉, 두 섹션에 한 번 이하).
- **신문 표제어 어휘 ban 리스트**: *봉인, 무대 위에 오르다, 변곡점, 거대한 파장,
  숨막히는, 격동의, 운명의, 칼끝, 풍전등화, 백척간두, 일촉즉발*. 비유 자체를 못
  쓰는 게 아니라 *극적 비유* 만 차단한다.

### 1.3 보수 표현 (추정·예측 영역)
- 사실 (출처 있는 수치·날짜·이벤트): 단정해도 OK. "X 는 12% 증가했다 (출처: Z)."
- 추정·예측·해석: 보수 표현 사용. *~로 보인다 / ~할 가능성 / ~로 추정된다 /
  ~할 수도 있다 / ~로 해석할 여지가 있다.*
  - 좋음: "이 정책은 단기적으로 환율을 절하 압력에 노출시킬 가능성이 있다."
  - 나쁨: "이 정책은 환율을 절하시킬 것이다." (단정)
- 출처 없는 추론은 *반드시* 보수 표현. evidence 추적성 원칙의 언어적 강화.

### 1.4 수사적 질문 자제
- "왜 하필 지금일까?", "이 결정은 누구에게 부담을 떠넘기는가?" 같은 수사적 질문은
  **보고서당 0~1회**.
- 1 섹션당 1~2회는 너무 많다 (v5.2.9 이전 가이드 폐기). 신문 칼럼 흉내가 된다.

## 2. 어휘 (Vocabulary)

### 2.1 학부생 수준
- 평이한 한국어 우선. 신문 사회면을 읽는 일반인이 막히지 않을 수준.
- 한자어·외래어 남용 금지:

| 나쁨 | 좋음 |
|------|------|
| 회임 | 맡김 |
| 제고 | 높임 |
| 함의 | 뜻하는 바 |
| 귀결 | 결과 |
| 부합 | 맞음 |
| 결부 | 엮임 |
| 소지 | 가능성 |
| 여하한 | 어떤 |
| 베이스라인 | 기준선 |
| 컨센서스 | 시장 전망 평균 / 시장 합의 |
| 내러티브 | 흐름 / 이야기 |
| 모멘텀 | 추진력 / 흐름 |
| 변곡점 | 흐름이 바뀌는 지점 |
| 익스포저 | 위험에 노출된 정도 |
| 가이던스 | 회사 자체 전망 |
| 헤지 | 위험을 줄이는 반대 거래 |
| rate card | 공시 요금표 (기본 단가표) |
| rate limit premium | 처리 한도를 높이는 대가로 더 내는 웃돈 |
| 1급 시민 (first-class citizen) | 곁다리가 아니라 정식 지원 대상으로 동등하게 다룸 |

영어 표현·업계 은어가 본문에 그대로 남는 것이 가장 흔한 위반이다 (WRITE-AP-10).
위 표는 예시일 뿐 — 표에 없어도 *뜻이 보존되면 평이한 우리말로 바꾼다* 가 원칙.

### 2.2 전문 용어 — 평이화 → 첫 등장 풀이 → 문단 하단 주석

§0.1 의 최우선 가치를 어휘 차원에서 구현하는 3단계 사다리. *위에서부터* 시도한다.

1. **평이화 (1순위)**: §2.1 어휘표처럼 평이한 우리말로 바꿀 수 있으면 바꾼다.
2. **첫 등장 한 줄 괄호 풀이 (2순위)**: 지명·개념·제도·약어가 *처음 등장* 할 때 한 줄
   괄호 풀이. 짧게 끝나면 이걸로 충분 — 주석까지 안 가도 된다.
   - "호른 아프리카 (소말리아·에티오피아·지부티·에리트레아 등 아프리카 동북단 지역)"
   - "우티 포시데티스 (식민지 독립 시 기존 행정 경계를 그대로 국경으로 인정한다는
     국제법 원칙)"
   - "EUV (극자외선 노광 공정)"
   - "PER (주가수익비율)"
   - 두 번째 등장부터 풀이 생략 OK.
3. **문단 하단 주석 (3순위 — 핵심 용어 한정)**: 평이화도 안 되고 괄호 한 줄로도
   부족한 *불가피한 핵심 용어* 는 그 용어가 등장한 섹션의 `ComposedSection.footnotes`
   배열에 적는다. 렌더러가 그 문단 *하단* 에 "용어 풀이" 블록으로 표시한다.
   - 형식: `{"term": "rate limit premium", "explanation": "처리 한도를 평소보다 높여
     달라고 요청할 때 추가로 내는 웃돈을 가리킨다."}`
   - `explanation` 은 일반 독자 눈높이 한두 문장. 마크다운 강조 금지.
   - 섹션당 0~4개. 같은 용어를 여러 섹션 주석에 중복 등록 금지 (처음 쓴 섹션 1회).
   - 평이한 말로 *바꿀 수 있는데* 주석으로 떠넘기지 말 것 (WRITE-AP-10).

- *한 문장에 새 개념 0~1개*. 한 문단에 새 개념 1~2개. 그 이상은 가독성 붕괴.

> 코드 SSOT: `ComposedSection.footnotes` (src/models.py) · composer SYSTEM_PROMPT 의
> "★ 최우선 원칙" 블록 · `freeform_essay.html` 의 `.freeform-footnotes` 렌더.

### 2.3 진부한 연결어 금지 (WRITE-AP-4)
- 금지: *다양한 측면에서, 결론적으로, 주목할 만한 점은, 다시 말해, 더 깊은 분석이
  필요하다, 심도 있게 살펴보면, 다각도로 조망하면, 시사하는 바가 크다.*
- 허용: *사실은, 단, 즉, 그러나, 반면, 핵심은.*
- 허용어조차 단정 톤 자제 — `핵심은` 은 한 보고서에 1~2회 한정.

### 2.4 마크다운 강조 금지 (WRITE-AP-1)
- 본문에 `*..*`, `**..**`, `_..__`, `>` 등 마크다운 기호 사용 금지. raw 노출되어
  "AI 가 쓴 글" 흔적이 된다.
- 강조가 필요하면 `pull_quote` 필드 별도 사용 (보고서당 0~2회).

## 3. 문장·문단

### 3.1 짧은 문단
- 한 문단 **3~5 문장**. 단락 사이 `\n\n`.
- 한 문장 평균 30~60자. 너무 긴 문장은 잘라서 둘로 나눈다.

### 3.2 'N번' vs 서수 (WRITE-AP-7)
- 서수 의미일 때 'N번' 형식 금지. *첫, 처음으로, 첫 번째, 가운데 첫* 사용.
- 'N번' 은 출입구·문항·후보 ID 뉘앙스.
  - 좋음: "유엔 회원국 가운데 처음으로 공식 승인이 나왔다."
  - 나쁨: "유엔 회원국 1번이 승인했다."

### 3.3 서수 모호 회피
- *처음으로 / 첫 / 첫 번째* 도 *맥락* 명시.
  - 좋음: "유엔 회원국 가운데 처음으로 공식 승인이 나왔다."
  - 나쁨: "처음으로 승인이 나왔다." (무엇이 처음인지 불명)

## 4. Editorial 컴포넌트 (절제된 사용)

본 시스템의 보고서는 `freeform_essay.html` 템플릿이 editorial 컴포넌트를 제공한다.
**사용 빈도를 절제** 한다 — 자주 박으면 시각·언어 피로.

| 컴포넌트 | 용도 | 보고서당 권장 빈도 |
|---------|------|-----------------|
| `kicker` | 한 줄 섹션 라벨 (예: "지정학적 변동") | 0~2 섹션 (도입부 위주) |
| `lede` | 본문 흐름 도입 1~3 문장 | 0~1 섹션 (첫 섹션 한정) |
| `analogy` | 어려운 개념 일상 비유 박스 | 0~1개. 정말 어려운 개념 한정 |
| `fact_grid` | 핵심 수치 격자 (3~6개) | 0~1개 |
| `dropcap` | 첫 글자 큰 글씨 | 0~1회. 첫 섹션 한정 |
| `pull_quote` | 핵심 인용·수치 강조 | 0~2개 |

### 4.1 lede 예시 (온건 톤)
- 좋음: "9월 27일, 미국은 베르베라항 사용권 확보를 공식 발표했다. 35년 만의
  외교 신호다."
- 나쁨 (극적): "35년의 봉인이 한 번에 풀렸다. 베르베라가 다시 무대 위에 올랐다."

### 4.2 analogy 작성 원칙
- 비유는 *어려운 개념을 평이하게 풀려는 도구*. 비유 자체가 화려할 필요 X.
  - 좋음 (기능적): "베르베라는 아프리카의 부산항. 부산이 일본·중국·동남아 환적의
    중심이듯, 베르베라는 홍해와 인도양을 잇는 환적 거점이다."
  - 나쁨 (극적): "베르베라는 거대한 게임판의 마지막 퍼즐."

## 4.1 broadcast_summary (X 구독자용 요약, v5.6.1)

보고서 *본문과는 별개 레지스터*. 보고서를 안 읽는 X(트위터) 구독자가 이 글만 보고도
맥락·핵심·시사점을 얻게 쓰는 친절한 평문. 규칙 SSOT 는 `narrative_composer.py`
SYSTEM_PROMPT 의 `=== broadcast_summary ===` 블록 (본 가이드는 사본 안 둠 —
anti-pattern #1):

- 해요체+습니다체 *혼합*, 한 문단 최대 2문장, 5~6 짧은 문단, 라벨·이모지·불릿 금지.
- 무슨 일 → 왜 → 그래서 무엇. 숫자는 문장에 자연스럽게.
- 마지막 문장은 전체 보고서로 부드럽게 안내하되 *매번 다른 표현* (고정 문구 = AI 티).
- 텔레그램 완료 메시지에 라벨 없이 첨부 (`ComposedReport.broadcast_summary`).

## 5. 차트·지도 본문 결합

- 차트 *직전* 단락에서 thesis 한 줄 미리 제시: "…의존도가 평균의 4배다 (아래 차트)."
- 차트 *직후* 단락에서 패턴을 한 단계 해석.
- 차트 단독 emit 금지 — 본문 흐름 안에서만.

차트 디자인·렌더링 SSOT 는 [docs/MONO_THEME_GUIDE.md](MONO_THEME_GUIDE.md), 회귀
패턴은 [docs/CHART_RENDERING_ANTIPATTERNS.md](CHART_RENDERING_ANTIPATTERNS.md).

## 6. 섹션 배치 (사건 성격별)

| 사건 유형 | 배치 |
|----------|------|
| 지리적 사건 (영토·항만·회랑·분쟁 지역·조약) | 지도 + 지리 맥락을 **상위 (1~2번째)** 섹션에 |
| 시계열 사건 (정책 진행·시장 추이) | 사실 타임라인 → 메커니즘 순 |
| 정량 비교 사건 (실적·수치·랭킹) | 핵심 지표 → 해석 순 |
| 공통 | 마지막 1~2 섹션은 모순·반대 가설 + 감시 신호 |

## 7. 출처 추적성

- 본문에서 *수치·날짜·구체 사실* 을 인용할 땐 가능하면 출처 URL 을 본문에
  '(출처: example.com)' 형식으로 표기하거나 `cited_sources` 에 정리.
- 출처가 없는 추론은 `§1.3` 의 보수 표현으로 명시 — "~로 추정된다" / "~할 가능성".
- 모순·반대 가설은 봉합하지 않고 드러낸다. `contradictions` 필드에 명시
  (Anti-pattern #5).
- **모순 섹션은 판단으로 착지한다 (WRITE-AP-9)**: `contradictions_heading` 을
  *내용 기반 판단형 제목* 으로 직접 짓는다 (예: '정전이냐 잠복이냐'). "봉합하지
  않은 충돌" / "모순" / "반대 관점" 같은 *정적 메타-라벨 금지* — 결론 회피 인상 +
  단조로움. `resolution` 은 어느 쪽에 무게를 두는지 *결론적 문장* 으로 써서 단락이
  판단으로 끝나게 한다 (각주 아님). side_a/side_b 는 각각 완결 문장.
