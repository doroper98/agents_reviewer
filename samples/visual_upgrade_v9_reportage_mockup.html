V9 VISUAL UPGRADE — DESIGN SHEET

르포 시각물 고도화 목업 PROPOSAL · 구현 전

르포 29건 실물 분석에서 확인된 갭 3개를 채우는 제안: ① 전황 지도 어휘(전선·공세 축·통제 구역·국면 전환) ② 사건 전개 타임라인(event_timeline) ③ 지리 무관 작전 스키매틱. 모든 색·패턴은 mono guide 준수(45° 단방향 해치, 잉크 농도 사다리, 액센트 1색). 데이터는 실제 르포 2건(2026-06-27 우크라이나 전선 / 2026-06-20 가와나카지마)에서 가져온 예시.

EXHIBIT R-1

전황 지도 — embedded_map 확장 어휘 (paths · zones · phases)

기존 지도는 점(markers)과 호(arcs)뿐이라 "전선이 어디에 있고 어느 쪽으로 밀리는가"를 그리지 못했다. 실제 사례: "포탄이 모자라 드론을 들었다 — 전선을 되돌리는 우크라이나" 르포의 지도는 마커 4개·호 1개가 전부였다. 제안: 전선(front) · 공세 축(advance) · 보급/우회로(route) · 통제/격전 구역(zones) + 국면(phase) 전환. 아래 국면 버튼을 눌러보면 전선과 공세 축이 시점별로 움직인다.

동부 전선, 겨울에서 여름까지
우크라이나 동부 · 국면별 전선 위치와 공세 축 (개략도 — 실제 전선의 단순화)
국면
전선·구역은 개략 표시다. 좌표는 본문 근거 지명 기준, 정밀 군사 경계가 아니다. (르포 표현 등급: 추론·개략 라벨 의무)
구현 스펙 (additive — 기존 payload 무변경 시 렌더 동일)
  • paths: [{points:[[lng,lat],...], kind:"front"|"advance"|"route", label?, side?:"a"|"b", phase?:1}] — front: 굵은 대비선 + 통제측 수직 틱, advance: 테이퍼드 화살표, route: 점선
  • zones: [{points:[[lng,lat],...], kind:"contested"|"control"|"buildup"|"strike", label?, phase?}] — 45° 해치 폴리곤 (kind 별 잉크 농도, hue 금지)
  • phases: [{id:1, label:"2월"}, ...] ≤4개 — 지도 하단 버튼, iv_skew 날짜 화살표 패턴 재사용. phase 없는 요소는 전 국면 공통
  • markers/arcs/rings 는 기존 계약 그대로. rings 는 도입(v7.5.0) 후 발행 실적 0회 — composer 결정 트리에 트리거 명문화 필요
  • 모션: 전선 stroke-dashoffset draw-in(기존 arc 패턴), 국면 전환은 500ms 보간, reduced-motion 시 즉시 상태
EXHIBIT R-2

event_timeline — 사건 전개 세로 타임라인 (신규 차트 type)

르포 5막은 시간 전개 서사인데, 현재 시점 사건(point event) 나열을 그릴 type 이 없다. gantt 는 기간 막대 전용이라 zero-duration 금지(CHART-AP-15), timeline_flow 는 르포에서 비활성. 그 결과 전개 시각화가 통째로 비는 르포가 많았다(29건 중 차트 0~1개인 르포 7건). 제안: 막(act) 밴드 + 날짜 스파인 + 전환점 강조.

수송기 한 대가 오가기까지
2026년 6~8월 · 모스크바 수송기 르포의 사건 전개 (예시 데이터)
◆ = 전환점(pivot). 막 라벨은 composer 가 emit 하는 서사 국면 이름.
구현 스펙 (신규 type — 9단계 절차 + osint 통지 필수)
  • data: {events:[{date:"2026-06-12", title, desc?, pivot?:true, act?:"발단"}], orientation?:"v"} — events 3~12개, pivot ≤3
  • 가드: 날짜 파싱 실패 행 drop, 3개 미만이면 emit 금지(validator 정합 — 빈 카드 방지), 동일 날짜 dodge
  • 르포: `_REPORTAGE_BLOCK` 의 "timeline_flow 또는 gantt" 모순 지시를 event_timeline 으로 교체. 일반 보고서: 사건 보고서 결정 트리에 편입
  • 모션: 스파인 draw-in 후 이벤트 노드 40ms 스태거 페이드 (기존 `_applyEntryAnimation` 프레임워크 확장, 신규 라이브러리 불요)
EXHIBIT R-3

작전 스키매틱 — 지리 무관 전술 국면 (embedded_map 의 basemap:"schematic")

가와나카지마 르포는 "별동대 우회 → 본대 선제 강하 → 회군 포위"라는 전술 서사가 핵심인데, world-atlas 110m 지도로는 분지 하나를 그릴 수 없어 시각화가 사실상 비었다. 제안: 베이스맵 없이 지형 힌트(강·산 리본)와 부대·기동 화살표만으로 그리는 스키매틱 모드. paths/zones/phases 어휘를 그대로 재사용한다.

안개 속의 반나절, 세 수
제4차 가와나카지마 (1561) · 개략 작전도 — 실축척 아님
국면
위치는 서사 기준 개략 배치. 스키매틱 모드는 축척·좌표계를 표시하지 않는다.
구현 스펙 (embedded_map additive — 신규 차트 type 아님)
  • basemap:"schematic" — world-atlas fetch 생략, terrain:[{kind:"river"|"ridge"|"road", points:[[x,y],...], label?}] 를 0~100 상대 좌표로
  • markers/paths/zones/phases 는 R-1 과 동일 계약 (lng/lat 대신 상대 좌표로 해석)
  • 발동 조건(프롬프트): 역사 전투·시설 내부·국지 전술 등 "국가 윤곽이 정보가 안 되는" 사건에만. 현대 지정학은 항상 실지도 우선
  • 지도 payload 하나로 처리 → osint 계약은 embedded_map additive 통지 1건으로 충분
V9 목업 · 렌더 코드는 제안 시연용 — 실제 구현은 maps.js/charts.js 의 기존 프레임워크(IntersectionObserver 진입, reduced-motion 게이트, 테마 토큰)에 편입한다. 외부 라이브러리 추가 없음(Anime.js 불채택 권고 — 근거는 docs/VISUAL_ENHANCEMENT_V9_PLAN.md §5).
