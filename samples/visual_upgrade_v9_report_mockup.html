V9 VISUAL UPGRADE — DESIGN SHEET

일반 보고서 시각물 고도화 목업 PROPOSAL · 구현 전

일반 보고서(기사형·브리핑)용 제안 3건: ① 르포와 공유하는 지도 확장 어휘(구역·사거리권 — 전선 제외) ② 사건 보고서용 event_timeline ③ 프롬프트↔가드 스키마 불일치로 발행 0건이 되어 있던 heatmap 의 소생. 일반 보고서 디자인 문법(둥근 모서리 · Newsreader 세리프 · editorial_cream)을 유지한다.

EXHIBIT S-1

지정학 지도 — zones · rings 어휘의 일반 보고서 개방

일반 보고서 306건 중 102건이 지도를 실었지만 사거리권(rings)은 v7.5.0 도입 이후 발행 실적 0회, 구역(zones)은 어휘 자체가 없었다. 대만해협·호르무즈 같은 단골 지정학 토픽은 점·호만으로는 긴장의 공간 구조를 못 그린다. 전선(front)·국면(phases)은 르포 전용으로 남기고, zones·rings 만 일반 보고서에 개방한다.

해협을 사이에 둔 세 겹의 압박
대만해협 · 훈련 구역과 미사일 도달권 (예시 데이터 — 실제 보고서 수치 아님)
구역 좌표는 개략 표시. radius_km 는 본문 근거 수치만 사용 (WRITE-AP-5 동일 원칙).
구현 스펙 (additive)
  • rings 는 기존 계약 그대로 — 코드 변경이 아니라 composer 결정 트리에 발동 트리거를 명문화하는 문제 (본문에 사거리·도달권·작전반경 수치가 있으면 rings 후보)
  • zones 는 르포 R-1 과 동일 계약. 일반 보고서 발동 조건: 훈련·봉쇄·분쟁 수역 등 면(面) 사건
  • maps.js 의 markers-필수 조건(maps.js:945 — 마커 0개면 지도 전체 미렌더) 을 markers·zones·rings·paths 중 1개 이상으로 완화
EXHIBIT S-2

event_timeline — 사건 보고서용 (라이트 변형)

일반 사건 보고서도 "무슨 일이 어떤 순서로 벌어졌나"가 뼈대인데, 현재는 point event 나열을 gantt(기간 막대 전용, zero-duration 금지)로 우겨넣거나 포기한다. 르포 R-2 와 같은 type 을 공유하되, 일반 보고서 디자인 문법(세리프 날짜, 둥근 카드)으로 렌더된다. type 1개 = 두 포맷 공용, 테마 토큰만 다르다.

칩값이 두 배가 되기까지
2026년 상반기 · 메모리 가격 사태 전개 (예시 데이터)
◆ = 전환점. 막 밴드는 composer 가 emit 하는 국면 이름 (선택 필드).
구현 스펙
  • 데이터 계약은 르포와 동일: {events:[{date,title,desc?,pivot?,act?}]}, 3~12개, pivot ≤3
  • 결정 트리 편입: "시간 순서가 서사의 뼈대인데 수치 축이 없다" → event_timeline (line/gantt 오용 차단 negative constraint)
  • 가드·템플릿 has_data·렌더러 경계값을 한 fixture 에서 3중 정합 검증 (신규 type 은 처음부터 parity 테스트와 함께 랜딩)
EXHIBIT S-3

heatmap 소생 — 2D 격자 (스키마 불일치 수정 후의 모습)

heatmap 은 SYSTEM_PROMPT 가 가르치는 데이터 모양([{title,severity}])과 validator 가 요구하는 모양({x,y,value})이 어긋나 있어, composer 가 프롬프트대로 만들면 100% 조용히 버려진다. 발행 실적이 0에 수렴한 이유가 "AI 가 안 골라서"가 아니라 배관 단선이었다. 수정 후 표준 형태: 국가×항목 2D 격자, 잉크 농도 사다리(≤4단), 액센트 0~1셀.

누가 어디서 아픈가
반도체 공급망 취약도 · 국가 × 병목 항목 (예시 데이터, 5=심각)
색조(hue) 대신 --text 불투명도 사다리. 최대값 1셀만 액센트 테두리.
구현 스펙 (버그 수정 — 최우선, 시각 신규 기능보다 먼저)
  • ✅ v8.5.11 반영 — heatmap 가드가 양형 수용: 격자형 [{x,y,value}](위 그림) + 강도 트랙형 [{title,severity}](v7.1.0 계약, 발행본 12건 재발행 하위호환). 렌더러엔 격자 분기를 추가(drawHeatmapGrid). stacked 는 가드를 렌더 계약 {scenarios} 으로 재작성
  • ✅ v8.5.11+14 반영 — 재발 차단: 등록된 전 type 에 대해 "프롬프트 문서 모양 → validate_chart_data 통과 → 템플릿 has_data 게이트 통과" 를 한 번에 검증하는 3중 parity 회귀(test_prompt_guard_parity.py). v8.5.12 가 2층만 검증해 gantt 카드 소멸 회귀를 재생산했고, v8.5.14 에서 3층으로 확장하며 그 클래스를 닫았다
  • ✅ v8.5.12 반영 — usage_log 를 emit(드롭 전)/kept(드롭 후) 2단 기록으로 확장. 드롭된 type 이 "기아"로 위장돼 자기교정 힌트가 깨진 type 을 더 밀어넣던 자기증폭 고리를 끊었다
